# 微信群消息自动读取 + 自动回复

在一台 Windows 电脑上挂着，自动读取指定微信群的消息并按规则回复。

回复走**三层决策链**，命中即停：

| 层 | 干什么 | 在哪配 | 成本 |
|---|---|---|---|
| **1. 业务指令** | 按你定义的指令去你自己的系统取数据并回复 | `handlers.py` | 零 |
| **2. 关键词规则** | 固定话术，秒回 | `settings.json` 的 `RULES` | 零 |
| **3. AI 兜底** | 智能对话，默认只在被 @ 时触发 | `settings.json` 的 `AI` | 按 token（可用免费模型） |

三层都没命中时不回复。

**为什么业务指令排在 AI 前面**：凡是有唯一正确答案的问题（编号、数量、金额、
状态这类），答案只能来自你自己的系统。交给 AI 它会编，而且编得很像真的。
所以这类问题先由业务指令拦下，AI 只负责它擅长的开放式对话。

两者也可以配合：`handlers.py` 支持先从你的系统取到真实数据，再交给 AI 用人话
组织成一句话回复（`return AIAnswer(数据)`）。此时 prompt 里已硬性要求
「只能基于这份数据回答，不许编造」，AI 只负责措辞，不负责事实。

## 完全免费开源

本项目**全部功能免费、开源**：单群监听、关键词回复、AI 智能回复、对接自己的系统、防封号措施、自检工具、打包与部署脚本，都在本仓库里，直接用即可。

## 使用前必读

### 1. 必须是 Windows

原理是读取 Windows 系统的界面自动化接口（本来给读屏软件用的），解析微信客户端窗口上的文字。
Mac / Linux 上没有对应能力。

找窗口、切会话、读消息、发消息这一层由项目自带的适配层 `wxui/` 实现，
只依赖开源的 `uiautomation`（Apache-2.0）。

### 2. 有封号风险，建议用小号

个人微信的第三方自动化违反《微信个人账号使用规范》。
程序内置了防封号措施（随机延迟、每小时限流、同人冷却），但**不能保证 100% 安全**。

### 3. 微信版本必须是 4.1.8.107，且要关掉自动更新

这是硬性要求，不是建议：

- **更高版本（4.1.13 及以上）用不了** —— 这些版本关闭了系统无障碍接口，
  任何基于界面自动化的方案都读不到内容，换库也没用
- **3.9.x 用不了** —— 微信服务端会以「版本过低」拒绝登录
- **微信会静默自动升级**，这是故障复发的头号原因。装好后必须堵掉自动更新

> 具体版本差异、自动更新的堵法、以及各类问题的排查手法，见
> [`docs/版本锁定与运行成本.md`](docs/版本锁定与运行成本.md)。

### 4. 运行环境要求

| 项目 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11 |
| Python | 3.12 |
| 微信客户端 | **4.1.8.107**（并已关闭自动更新） |
| 依赖 | 只需 `uiautomation`，`pip install -r requirements.txt` 即可 |
| 桌面会话 | 必须是**已登录的交互式桌面**。停在登录界面或锁屏时，界面自动化跑不了 |
| 微信窗口 | 保持打开，别最小化到托盘 |
| 远程管理 | 别用 Windows 自带远程桌面（断开会锁屏），用 ToDesk / 向日葵这类不锁屏的 |

长期挂机建议开启 Windows 自动登录，否则机器重启后机器人起不来。

## 能做什么 · 不能做什么

先看清楚边界，避免买了才发现不合用。

### 已经能做（都经过实机验证）

- 盯住**一个**微信群，自动读取新消息
- 按关键词规则固定回复（零成本、秒回）
- 被 @ 时用 AI 智能回复（需自备 API key，可用免费模型）
- 对接你自己的系统，回答"只有你的系统知道答案"的问题
- 自动识别并跳过机器人自己发的消息（不会自问自答）
- 同一个人连发多条相同内容，每条都能独立识别
- 发送前复核目标会话，**宁可不发也不会发错群**；发送后回读界面确认
- 防封号：随机延迟、同人冷却、同群冷却、每小时上限

### 目前做不到

| 做不到 | 说明 |
|---|---|
| **同时盯多个群** | 一个实例只能盯一个群。多群需要多开或后续版本 |
| **回复时 @ 对方** | 微信的 @ 需要从候选列表挑人，无法在发送前确认挑对了。为了避免 @ 错人，改成在正文里带称呼 |
| **稳定获取每条消息的发送者昵称** | 多条消息在同一瞬间到达时，只有最后一条能拿到昵称，其余显示为「群成员」。如果你依赖严格的白名单/黑名单，这一点要先评估 |
| **处理图片、文件、语音** | 只处理文字消息，其余自动跳过 |
| **在微信 4.1.13 及以上运行** | 那些版本关闭了系统无障碍接口，任何界面自动化方案都读不到内容 |

## 快速开始

```bat
:: 1. 自检 + 自动装依赖
python check_env.py --install

:: 2. 改配置（见下一节）
::    LISTEN_GROUPS  填群名，从自检输出的会话列表里复制，必须一字不差
::    MY_NICKNAME    填机器人这个号的昵称
::    DRY_RUN        先保持 true

:: 3. 演习跑 —— 一条消息都不会真发，只记日志
python bot.py

:: 4. 看 logs/messages.log 确认读得对、决策对，再把 DRY_RUN 改成 false
```

日志位置：

| 文件 | 内容 |
|---|---|
| `logs/bot.log` | 运行状态、决策过程、发送结果 |
| `logs/messages.log` | 收到的每一条消息 |

## 配置

配置有两处，**`settings.json` 覆盖 `config.py`**：

| 文件 | 用途 |
|---|---|
| `config.py` | 默认值。源码运行时改这里最方便 |
| `settings.json` | 外置配置。**打包分发后只能改这个**（复制 `settings.example.json` 得到） |

嵌套配置**逐层合并**：`settings.json` 里只写 `{"AI": {"enabled": true}}`，
`AI` 下其他项仍沿用 `config.py` 的默认值，不会被整块清空。

> ⚠️ **API 密钥请写在 `settings.json` 里，不要写进 `config.py`** ——
> `config.py` 是要进版本库的，`settings.json` 已在 `.gitignore` 中。

### 关键词规则

```json
"RULES": [
  {
    "keywords": ["在吗", "在不在", "有人吗"],
    "reply": "在的 {sender}，有什么事你说～",
    "mode": "contains"
  }
]
```

- `mode`：`contains`（包含）或 `exact`（整条完全相等）
- `reply` 里可用 `{sender}` `{group}` 占位符

### AI 智能回复

国内主流大模型都兼容 OpenAI 接口格式，**换厂商只改三个值**：
`preset` / `model` / `api_key`，代码一行不用动。

```json
"AI": {
  "enabled": true,
  "providers": [
    { "preset": "zhipu", "api_key": "你的key", "model": "glm-4-flash-250414" },
    { "preset": "zhipu", "api_key": "你的key", "model": "glm-4.7-flash" }
  ]
}
```

`providers` 是**按顺序降级**的：第一个失败或被限流会自动切下一个，并带熔断。
推荐主力放免费模型、备用再放一个，避免单一模型被挤爆时整个 AI 层失效。

| 预设 | 说明 |
|---|---|
| `zhipu` | 智谱 GLM。**Flash 系列永久免费、不限总量**，限制在并发。首选 |
| `deepseek` | 付费但便宜，中文强 |
| `qwen` | 通义千问。新用户有免费额度，会过期 |
| `kimi` / `doubao` / `baidu` | 见 `ai_provider.py` 里的 `PRESETS` |
| `custom` | 任何 OpenAI 兼容端点，包括本地 Ollama / vLLM |

拿 key 的地址和各家对比：跑 `python ai_provider.py`。
**接进机器人之前先单测 key 通不通**：

```bat
python ai_provider.py zhipu 你的KEY
```

> 模型名和价格会变动，以各家官方定价页为准。
> 免费模型的选型建议见 [`docs/版本锁定与运行成本.md`](docs/版本锁定与运行成本.md)。

**省钱开关**：`only_when_at_me` 默认 `true`，只有 @ 机器人才调用 AI。
关掉的话群里每句话都烧 token，且容易刷屏，慎重。

### 接入你自己的系统

让机器人能回答"只有你的系统知道答案"的问题。两种接法，可只开一个也可都开，
改完跑 `python backend.py` 测连通性。

| 模式 | 原理 | 取舍 |
|---|---|---|
| **`http`**（推荐） | 机器人调你后端的 REST 接口，后端去查库 | 数据库密码不落在这台 Windows 上，业务逻辑改起来方便 |
| **`mysql`** | 机器人直连数据库 | 不用后端配合；但密码存在本地，且这台机器要能连到库 |

**定义一条自己的指令**（`handlers.py`）——
`pattern` 决定群里发什么触发它，函数体决定怎么取数据、回什么：

```python
def handle_my_cmd(ctx):
    # ctx.args -> 从群消息里正则捕获到的参数
    # ctx.db   -> 数据库连接      ctx.api -> 你的后端接口
    rows = ctx.db.query("SELECT ... WHERE id = %s", (ctx.args[0],))
    return f"查到了：{rows}"                          # 直接回复这段文字
    # 或 return AIAnswer(rows, hint="用一句话播报：")   # 交给 AI 组织措辞

HANDLERS.append({
    "name": "我的指令", "usage": "xxx <参数>",
    "pattern": r"^xxx\s*(\S+)", "func": handle_my_cmd,
})
```

自带 4 个可直接照改的示例。

**内置的安全限制**（请勿绕过）：

- SQL 一律**参数化**（`%s` 占位符）。群消息内容只能作为参数传入，不能拼进 SQL——防注入
- 写操作默认关闭，需显式开启 `allow_write`
- **`DELETE` / `DROP` / `TRUNCATE` / `ALTER` 在代码层面硬性禁止**，即使开了 `allow_write` 也不行。
  这个机器人由群消息触发，不能让群里发一句话就把表删了

**把群消息存档**：需要留存聊天记录做统计或审计时，把 `save_messages.enabled`
打开即可，收到的每条消息会自动入库。MySQL 模式下会自动建表，
表结构见 `backend.py` 的 `CREATE_TABLE_SQL`。

## 防封号措施

`settings.json` 里可调，**不建议全关**：

| 配置项 | 默认 | 作用 |
|---|---|---|
| `REPLY_DELAY_RANGE` | 2~5 秒 | 回复前随机等待。秒回是最明显的机器特征 |
| `PER_SENDER_COOLDOWN` | 30 秒 | 同一个人的重复回复间隔 |
| `PER_GROUP_COOLDOWN` | 5 秒 | 同一个群的回复间隔 |
| `MAX_REPLIES_PER_HOUR` | 40 条 | 每小时全局上限 |
| `ONLY_REPLY_WHEN_AT_ME` | `false` | 改 `true` 则只在被 @ 时回复，最不惹人烦 |

代码里另外硬性做了两件事：

- **绝不处理机器人自己发的消息** —— 否则会自己回自己，无限循环
- **消息去重** —— 同一条消息不会被重复处理

## 打包分发

### 方案一：绿色免安装版（推荐）

```bat
python build_green.py             :: 打绿色版
python build_green.py --zip       :: 顺便压成 zip
```

产出一个文件夹，内含 Python 运行时，**目标机器不用装 Python**，双击 bat 即可运行。

### 方案二：exe

```bat
pip install pyinstaller
python build_exe.py --console     :: 调试期建议加 --console 看日志
```

### 为什么推荐绿色版

| | exe | 绿色版 |
|---|---|---|
| 兼容性 | 底层 COM 组件需要运行时写缓存，打包后容易出错 | **没这个问题**，就是个真实 Python 环境 |
| 杀软误报 | 较高。"自动操作微信"的 exe 行为特征本就容易被启发式检测拦 | 明显更低 |
| 改业务逻辑 | 要重新打包 | **改 .py 存盘即可** |
| 改配置 | 靠外置 `settings.json` | 同左 |

即便用绿色版，仍可能被 360 / 火绒拦截，加白名单即可。

## 常见问题

**连不上微信**
先确认：微信登录了吗？主窗口开着吗（不能缩到托盘）？Windows 是不是停在锁屏？
再确认微信版本是不是 4.1.8.107 —— 版本不对是最常见的原因。
装的是 4.1.13 及以上时，启动日志会直接写
`连不上微信: AccessibilityUnavailable: 微信窗口没有实现无障碍接口（WM_GETOBJECT 返回 0）`——
这是版本问题，不是群名填错，等多久、重启多少次都没用。
腾讯电脑管家之类的安全软件也可能拦截界面自动化。

**监听某个群失败**
群名必须一字不差，空格和 emoji 都算。跑 `check_env.py`，从输出的会话列表里复制。

**收不到消息**
跑 `python diag_receive.py "群名"`，它会分段自检并告诉你卡在哪一步，全程不发消息。
也可以看 `logs/bot.log`：正常情况下会有 `已盯上: xxx`，收到消息时会有 `收到 ...`。
注意**机器人自己发的消息不会触发回复**，测试时要用别的号发。

**跑着跑着全部失效**
八成是微信自动更新了。跑 `python bot.py` 看启动时打印的微信版本，
按 [`docs/版本锁定与运行成本.md`](docs/版本锁定与运行成本.md) 降级并堵掉自动更新。

**AI 不回复**
检查 `only_when_at_me` 是不是 `true`（默认只在被 @ 时才调 AI），
以及 `MY_NICKNAME` 填了没。用 `python ai_provider.py <preset> <key>` 单测模型通不通。

**回复里称呼是「群成员」**
说明那条消息的发送者昵称没读到。多条消息同时到达时会出现，属于已知限制，
不影响回复本身。

**有回复但没发出去**
先看 `logs/bot.log` 里有没有这几种：`冷却中`（同一个人短时间内已经回过）、
`每小时上限`、`目标不匹配`。**这三种都是程序故意不发，不是故障。**
觉得太保守可以在 `settings.json` 里调 `PER_SENDER_COOLDOWN` 等参数。

**打包成 exe 后报错**
改用 `build_green.py` 打绿色版。
